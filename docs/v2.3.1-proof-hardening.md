# V2.3.1 Proof and benchmark hardening

This pass separates two claims that must not be conflated.

## Benchmark modes

`execution-efficiency` measures the orchestration strategy with Project Intelligence empty for
every pair. Baseline and UAP begin each task from the same predeclared source checkpoint. It can
measure immediate execution overhead or benefit, but it cannot prove learning.

`longitudinal-learning` maintains two independent source lines. Baseline task N+1 starts from the
accepted Baseline task N output. UAP task N+1 starts from the accepted UAP task N output plus its
project-local `.agent` intelligence. Source trees are never exchanged between the lines.

```bash
python scripts/pocketflow_longitudinal_benchmark.py --dry-run \
  --provider codex --mode longitudinal-learning

python scripts/pocketflow_longitudinal_benchmark.py --execute \
  --provider codex --model <model> --reasoning low \
  --mode execution-efficiency \
  --workspace build/pocketflow-execution-efficiency \
  --output benchmark-results/pocketflow-execution-efficiency.json

python scripts/pocketflow_longitudinal_benchmark.py --execute \
  --provider codex --model <model> --reasoning low \
  --mode longitudinal-learning \
  --workspace build/pocketflow-longitudinal-learning \
  --output benchmark-results/pocketflow-longitudinal-learning.json
```

Use `--resume` only with the retained workspace and result file from the same mode. Completed
pairs and separate Baseline/UAP checkpoints are preserved. Authentication, quota, harness, and
source-lineage failures stop the run before more quota is spent.

## Quality contract

Quality equivalence is determined only by the fixed suite at
`benchmark-fixtures/pocketflow/acceptance/contract.py`. The provider does not receive ownership of
this file. Both sides run this exact suite. Candidate-authored tests are recorded as informational
evidence and never define paired validity.

The contract covers CRUD and SQLite persistence, React build/API/loading/error behavior, category
filtering and totals, a month-boundary regression, and monthly API/UI reporting. A pair is
`QUALITY_EQUIVALENT` only when both sides pass the same required checks.

## Evidence semantics

Every result uses one of: `VALID`, `INVALID_QUALITY`, `INVALID_HARNESS`,
`INTERRUPTED_PROVIDER`, `QUOTA_LIMIT`, or `NOT_COMPARABLE`.

The learning funnel records provider evidence, distiller candidates and rejection reasons,
persistence decisions by kind, and materialized project Skills. The reuse funnel separately
records candidates considered, selected context by kind, context size, stale source reasons, and
`validated_context_reuse`.

Validated context reuse means that an item was selected into context and the task and external
evaluation succeeded. It does not prove that the model semantically relied on the item. Repository
rediscovery avoidance remains `UNAVAILABLE` unless a provider reports observable file exploration.

## Current evidence status

Earlier PocketFlow JSON files remain historical observations. They used generated/self tests or a
shared canonical checkpoint at parts of the sequence, so they do not satisfy this hardened
protocol and must not be marketed as proof of amortized savings. The Codex sequence did observe
reusable context, but consumed more cumulative measured tokens; it did not reach break-even.

No new full real-provider run is part of this code-hardening pass. The mandatory offline
three-fresh-Orchestrator test and benchmark dry-run must pass first; then one bounded
`longitudinal-learning` run can produce new claimable evidence.
