## 驗收事故與修正

首次 R1 研究題把 `"B"` 當成錯誤，卻接受語義相同的 `"Intervention B"`。模型重複收到同一個模糊 `recommendation` 失敗，導致不必要的修正。舊 R1 保留但不作政策證據；修正後離線驗證兩個保留成品均通過。

現在研究驗收接受兩種等價表達；本 pilot 額外啟用 no-progress gate，同一失敗簽章連續兩次、且沒有新通過檢查時停止重試。此 gate 是 opt-in，沒有改掉其他 benchmark 的既有收斂規則。

## 九類任務的分層判斷

結合 [程式三規模](legacy-scale-sol-cap-20260916-r2.md)與[設計三域](design-cap-sol-20260916-r1.md)：

| 類別 | cap6/plain 的描述性結果 |
|---|---|
| 程式 small／medium／large | +26.75%／−10.76%／−18.23% |
| UI/UX／平面／3D | −1.35%／+1.27%／−17.44% |
| 研究／產品／照明 | +9.96%／+0.36%／+1.00% |

結果高度異質，不能用跨域平均決定全域策略。尤其 small 程式與研究明顯反向，UI/UX、平面、產品與照明接近平手。維持 normal 預算為預設；cap6 只能在相同任務族群、相同模型與驗收品質等價的多組證據支持後局部啟用。

限制：除程式三規模各兩組外，其餘每域只有一組；沒有主觀設計品質、實際使用性或完整語義評審。所有執行都未證明硬 cap 觸發，因此差異可能是模型路徑變異與預算提示效應。
