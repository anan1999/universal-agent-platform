## Initial blocker classification

### Blocker

No confirmed source blocker at baseline. Git-branch installation, wheel
installation, and source-checkout independence remain hard acceptance gates
until their isolated tests pass.

### Important

- The Dashboard did not expose the effective consumption mode or its useful
  limits and omitted provider/invocation fields from token-usage responses.
- The documented development extra did not install the standard `build`
  frontend required by `python -m build`.
- OpenAI-compatible error acceptance did not explicitly cover authentication,
  invalid models, and malformed responses or prove that these configuration
  failures do not trigger stronger-model escalation.
- Cross-provider tests proved routing but not actual dependency receipt handoff.
- Explicit economy safety, profile fan-out, and capability-resolution-order
  regressions were missing.

These findings are being fixed without changing the V2 architecture or adding
providers, profiles, or permanent agents.

### Nice to have

- The test environment reports one upstream Starlette/httpx deprecation warning.

### Future

- Additional real provider adapters beyond Codex and OpenAI-compatible.
- PyPI publication. The manifest truthfully keeps `from_pypi` set to `null`.

## Architecture audit

The generic core contains no provider/model routing conditionals for Codex,
Luna, Sol, Astra, or GPT model names. The only `codex` match in
`src/adaptive_agent/core` is a provider-independence statement in a module
docstring. Provider-specific construction remains in the provider registry and
adapters. Consumption policies contain only resource budgets and cost/reasoning
biases; they do not map roles to providers or models.
