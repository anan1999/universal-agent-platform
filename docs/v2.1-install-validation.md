# V2.1 installation validation

Validated on Windows with Python 3.11 in clean virtual environments on 2026-09-07.

## Distribution build

`python -m build` produced both `universal_agent_platform-2.1.0.tar.gz` and
`universal_agent_platform-2.1.0-py3-none-any.whl`. The build log confirmed that every built-in
profile, model/config file, project template, Dashboard asset, and provider module was included.

## Wheel installation

A new venv installed the wheel with public dependencies. From a separate empty project
directory, with no source path on `PYTHONPATH`, the following passed:

1. `agentctl --version` returned `2.1.0`.
2. `agentctl setup --auto` passed twice.
3. `agentctl init --auto --dry-run` detected the `general` profile.
4. `agentctl init --auto` passed twice without duplicating the marker or replacing settings.
5. `agentctl doctor` passed with schema v5, 10 profiles, and 8 models.
6. Package resource checks found models, profiles, templates, and Dashboard files under the
   venv's `site-packages/adaptive_agent/resources` directory.

This verifies source-checkout independence: runtime loading uses the installed package, not
the repository root.

## Git URL installation

The validated release candidate was installed directly from the public feature branch:

```bash
pip install git+https://github.com/anan1999/universal-agent-platform.git@feature/v2.1-zero-friction
```

Pip resolved public commit `738623c33e1934b8dfef75c2a5614837a428f4db`, built the wheel,
and installed version 2.1.0. The same separate-project setup/init/doctor/resource checks passed,
as did the offline cross-provider demo.

The permanent recommended command intentionally omits a branch:

```bash
pip install git+https://github.com/anan1999/universal-agent-platform.git
```

It will install V2.1 from the default branch after the reviewed feature branch is merged. The
validation did not push directly to or merge `main`.
