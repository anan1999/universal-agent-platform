# 品質達標總成本量測

2026-09-16：舊三軌報告量到的是部分通過配對的成本，不是交付總成本。
失敗後修復費用曾被覆寫，且使用另一臂的 checkpoint 繼續，不能用來推算實際完成專案的總消耗。
既有報告保留作除錯證據，不應宣稱其結果代表使用者達到相同品質所需的成本。

新入口：`python scripts/quality_completion_benchmark.py --execute --workspace <new-directory>`。
執行固定使用 `gpt-5.6-sol`，Baseline 與 UAP 都取消 benchmark 特設的工具次數上限。
三個題目是需求變更，不是修復對話次數限制；每個需求持續修改直到合約通過。

- 兩臂各自保留作品；修復從自己的失敗版本繼續，不能借用對方成果。
- 同一個獨立驗收器回傳具體缺失，交給原臂修復並重驗全部累積要求。
- 每次呼叫開始及結束都寫入 SQLite，失敗、修復、最後一次成功的成本全部累加。
- 400,000 Token / 900 秒是每臂每需求的資源保護線，不是品質完成定義。
  單次呼叫可能超過剩餘 Token 預算；超出數據仍完整計入。
- 未達標且預算耗盡，回報 unfinished；量測不完整回報 measurement_incomplete。
  未回報 Token 不能推論零消耗，不自動把它當成免費重試。
- 模型固定且核對 receipt；各輪交替執行順序，所有觀測成本包含不成功輪。

## 尚未完成的品質層

目前既有驗收器主要看 HTML/SVG/OBJ 結構與規格，仍有字面比對、未公開的圖層 ID
要求等限制。因此新 runner 只回報 contract_passed，永不自動宣稱設計品質或品質等價節省。
正式品質 benchmark 還需要預先鎖定且兩邊可見的評分規格，以及：

- UI/UX：實際鍵盤、表單、錯誤狀態與不同螢幕尺寸的互動測試。
- 平面：實際渲染的可讀性、溢出、對比、文字層級與版面完整度。
- 3D：實際渲染、部件幾何、材質、相交與可用性，而非只檢查群組名稱存在。
- 隱藏 arm 身分的視覺評閱及一致達標門檻；需要修正時累加修正成本。
- 如使用 AI 評審，其 Token 需獨立記帳並列入總成本；現行 runner 不呼叫 AI 評審。

在這層完成前，先用離線故障序列驗證記帳，避免花真實額度得到另一份品質證據不足的報告。
