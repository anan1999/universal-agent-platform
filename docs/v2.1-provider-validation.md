# V2.1 provider validation

## Offline contract tests

Normal pytest uses an injected HTTP transport and consumes no provider quota. It covers
successful responses, measured usage parsing, secret redaction, unconfigured state, timeouts,
and hard capability rejection.

## Bounded real OpenAI-compatible validation

Validated on 2026-09-07 against the local Ollama OpenAI-compatible endpoint. No model was
downloaded and no project file was exposed or modified.

- Endpoint type: local OpenAI-compatible API
- Runtime: Ollama
- Model: `qwen2.5-coder:7b`
- Probe: `GET /v1/models`, connected
- Tiny provider test: completed in 18.64 seconds
- Tiny-test usage: 36 input, 11 output tokens; source `measured`
- Reasoning-only test: completed in 10.58 seconds
- Reasoning usage: 46 input, 33 output tokens; source `measured`
- Reasoning result: correctly explained that an API-only backend lacks local filesystem and
  command access
- Secret handling: no API key was required; tests prove configured values are not serialized

The tiny model wrapped `UAP_PROVIDER_OK` in a JSON code fence rather than returning the exact
bare string. This is a model instruction-following limitation, not a transport failure, and is
recorded rather than hidden.

The adapter advertises `api_reasoning`; filesystem, repository, shell, and write access are
unsupported. Routing tests prove it is selected for reasoning-only work and rejected for local
file modification even when it is the preferred provider.
