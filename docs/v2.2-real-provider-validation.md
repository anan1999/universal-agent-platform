## Defects found while establishing acceptance

Before the passing benchmark, Codex CLI 0.153.4 exposed two provider integration defects:

1. A write run using only `--sandbox workspace-write` could not obtain managed approvals. Five
   completed Codex calls returned `blocked`; their provider-measured aggregate was 320,617 input,
   239,232 cached-input, and 4,125 output tokens. UAP incorrectly escalated two of those blocked
   results. One additional in-flight retry was interrupted; its usage is unavailable.
2. The first correction combined `--approve-for-me` with `--sandbox`, which this CLI version rejects
   as mutually exclusive. Two attempts failed before inference with usage unavailable/zero recorded
   tokens.

The final implementation uses `--approve-for-me` by itself for write tasks, retains explicit
`--sandbox read-only` for read-only tasks, classifies policy blocks and invalid arguments as
environment failures, and prevents stronger-model escalation for those failures. A preliminary
sandboxed harness run was not retained due an early fixture-cleanup bug, so its token metrics are
`UNAVAILABLE`; it is not included in either benchmark column.
