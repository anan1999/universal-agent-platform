# V2.3.1 Learning Loop

V2.3.1 makes project learning evidence-gated and inspectable. Execution produces structured
evidence; `IntelligenceDistiller` classifies it without an extra provider call; the store applies
quality and expected-reuse gates; later runs select current reusable items before source
rediscovery; and successful evaluations record validated context reuse.

Historical receipts and task history remain bounded evidence, but do not count as reusable
intelligence or advance maturity. Maturity reaches `learned` only after a validated reusable item
is selected by a successful warm run with a passing evaluation. Failed runs can still leave a
compact receipt, but cannot create validated context reuse.

Inspect the result with:

```bash
agentctl intelligence explain
agentctl context explain "continue the project API work"
agentctl status --json
```

Skill and agent candidates require explicit, project-specific evidence and expected reuse. Generic
procedures are rejected, and candidates remain temporary until repeated validated context use demonstrates
payback. Source hashes invalidate knowledge, commands, decisions, skills, roles, evaluations and
known issues when their related files change.

Amortization accepts paired baseline/UAP sequences and quality flags. A cumulative break-even is
reported only when every comparison through that point has comparable measured costs and passed
quality; otherwise the result is `NOT_CLAIMABLE`.

No learning AI call is made by default. If a future adapter needs one, its invocation and token
cost must be recorded as a learning investment.

The hardened proof protocol and its two distinct hypotheses are documented in
[V2.3.1 proof hardening](v2.3.1-proof-hardening.md).
