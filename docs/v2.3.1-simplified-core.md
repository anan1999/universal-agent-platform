# V2.3.1 simplified core

The default runtime now tests one narrow hypothesis: a fresh AI session should not have to
rediscover repository structure that a small, verified map already records.

## Default hot path

```text
Goal -> .agent/project-index.json -> relevant paths -> optional procedure Skill
     -> one AI executor -> deterministic validation -> compact receipt
```

Project-index construction and retrieval are deterministic. They make zero AI or network calls,
do not use embeddings, and inspect only high-value root files plus top-level directories. The index
targets 4 KiB and refuses to grow beyond 8 KiB without moving detail elsewhere.

`.agent/cache/files.json` contains only files reported useful by successful validated work. Each
entry has a SHA-256 hash, bounded summary, important symbols and verification time. A hash change
removes the stale summary on its next read. The cache never pre-indexes the repository.

## Classification

- Core: goal analysis, one executor first, provider routing, Project Context Index, relevant-path
  retrieval, optional procedural Skills, deterministic tools, source invalidation, artifact
  evaluation and structured receipts.
- Optional: multi-agent DAGs, project Skills, decisions and known issues.
- Experimental/analytics: Agent-role learning, automatic Skill synthesis, maturity routing,
  promotion lifecycle, payback and amortization analytics.
- Legacy-compatible: `.agent/intelligence.json` and its CLI explain views remain readable.

Experimental switches default to OFF:

```text
UAP_EXPERIMENTAL_AGENT_LEARNING=1
UAP_EXPERIMENTAL_SKILL_SYNTHESIS=1
UAP_EXPERIMENTAL_MATURITY_ROUTING=1
UAP_EXPERIMENTAL_MULTI_AGENT=1
UAP_EXPERIMENTAL_HEAVY_LEARNING=1
```

Maturity routing is retained only as a compatibility flag placeholder; normal routing never reads
project maturity. Payback remains available in `agentctl intelligence explain` and benchmark code,
not the execution hot path.

## Commands

```bash
agentctl init --auto
agentctl context
agentctl context explain "Add a monthly report" --json
agentctl run "Add a monthly report"
agentctl status
agentctl status --debug
```

Normal status shows architecture, index size, cached file count, project Skill count and last task.
Legacy lifecycle metrics appear only with `--debug` or `agentctl intelligence explain`.

## Isolated benchmark

The five-task longitudinal benchmark is retained as experimental history. The primary experiment is
now one ordered pair with the same fixture source, provider, model, task and benchmark-owned
acceptance contract:

```bash
python scripts/context_cache_benchmark.py --dry-run \
  --workspace build/context-cache-dry \
  --output benchmark-results/context-cache-dry.json

python scripts/context_cache_benchmark.py --execute \
  --provider codex --model <model> --reasoning low \
  --workspace build/context-cache-real \
  --output benchmark-results/context-cache-pair.json \
  --report docs/context-cache-pair-results.md
```

The executable path makes exactly two provider calls: Fresh Baseline, then Fresh UAP with compact
context. It records only measured provider tokens, cache tokens, duration, invocation count,
external acceptance, file reads when available, and UAP-controlled context characters.

No current benchmark establishes a general token-saving percentage. A benefit claim is eligible
only when both sides pass the identical external acceptance contract and UAP uses fewer measured
tokens or materially less observable work.
