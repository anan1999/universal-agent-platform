# V2.3.1 Learning Pipeline Correctness

Workers can return compact externalized `learning_evidence` in their structured receipt. UAP
collects that field from persisted receipts after execution and sends it to the provider-free
`IntelligenceDistiller`. The distiller maps public evidence types (`knowledge`, `decision`,
`command`, `evaluation_rule`, `known_issue`, `procedure`, and `agent_role`) into normalized
candidates, rejects missing/generic evidence, and deduplicates equivalent candidates.

Procedures with project-specific evidence become temporary, review-required project Skills in the
existing V2.2 package format under `.agent/skills/`. They are not trusted or promoted automatically.
First-use and repeated-use counters are separate from measured payback. Agent roles begin as
`needs_review` candidates and never become active from one task.

Historical receipts remain excluded from reusable maturity. A selected item only becomes validated
context reuse after a successful run and passing evaluation. This records successful selection, not
semantic reliance. Legacy run records without explicit success or evaluation fields are unknown and
do not count.

The PocketFlow harness supports an offline `--dry-run` mode and two separate real modes. In
`execution-efficiency`, each pair shares a predeclared checkpoint and Project Intelligence starts
empty. In `longitudinal-learning`, Baseline and UAP preserve independent source lines and are never
cross-pollinated. Both use the same benchmark-owned external acceptance suite. See
[proof hardening](v2.3.1-proof-hardening.md).
